# Agent Eval Results - 2026-08-03

Second full real-agent eval round for issue
[#2](https://github.com/galjos/odh-cli/issues/2), run against the manual
protocol in [docs/evaluation.md](../../../docs/evaluation.md). First round
since v0.4.1/v0.4.2 changed the warning surface.

## Setup

- CLI: `0.4.2-dev`, commit `f9f6adaaf128`, built from `main`, darwin/arm64.
- One fresh agent attempt per `tasks.json` prompt (13 independent LLM
  coding-agent attempts). Each agent received only the built binary, the
  skill bundle (`skills/open-data-hub-cli/SKILL.md`), and `recipes.json`.
  Agents were explicitly barred from reading `tasks.json`, repo source, and
  the web.
- Scored afterwards against `pass_criteria` and `common_failures` by
  independent judges who re-ran the load-bearing commands rather than
  trusting the attempt transcripts.
- Warning changes under test for the first time: data-derived frozen-feed
  disclosure, always-on `--limit` truncation reporting, upstream HTTP errors
  propagating instead of surfacing as empty results, and the match-total
  warning when `--limit` caps a filtered result.
- Live upstream conditions during the round: `odh doctor` green throughout
  (6/6 checks, all data endpoints HTTP 200); the 132 MB STA GTFS archive
  failed to download repeatedly against the hardcoded 2m budget, blocking
  the transit command family for 20+ minutes at a time; the PROVINCE_BZ
  Mobility Timeseries event feed is frozen (newest `transaction_time`
  2025-10-13, 2025-07-23 excluding stale rows); `openapi transmodel` failed
  on an expired TLS certificate.

## Failure Analysis And Fix Categories

Per the protocol, each issue is assigned a fix category.

1. GTFS static archive fetch is a hard block for the whole transit family
   (4 attempts affected; 1 partial caused directly). Confirmed in source:
   `internal/commands/transit.go:38` hardcodes `gtfsDownloadTimeout = 2 *
   time.Minute` and line 1070 wraps the parent context with it, so the
   global `--timeout` - including `--timeout 0` - cannot raise it. Partial
   downloads are discarded, so retries never accumulate, and
   `odh call gtfs /v1/dataset/sta-time-tables/raw` hits the 50 MiB cap at
   `internal/client/client.go:141` against a 132 MB archive, so there is no
   fallback. Category: **narrow CLI feature**. Repeated across four attempts
   this round and already recorded as a live condition in round 1.
2. JSON-default commands reject `--json` / `--format json` (5 occurrences
   across 5 tasks: `diagnostics ev-charging` x2, `apis` x2, `mobility
   events`, `diagnostics parking-forecasts`). Round 1 logged this as
   "track it and apply if it recurs in the next round". It recurred.
   Category: **narrow CLI feature**, now justified.
3. `recipes.json` `ev-current-availability` hardcodes `--origin ALPERIA` in
   three of five commands and `--limit 1000` for origin discovery;
   `SKILL.md:110` uses ALPERIA as its diagnostics example. ALPERIA is 7,677
   stations, 100% inactive, newest row 2024-09-17, every value 0 - and at
   `--limit 1000` it is the *only* origin discovery returns. An agent
   following the recipe verbatim reports "no chargers" from two-year-old
   data. Category: docs or skill guidance.
4. `recipes.json` `parking-current-plus-forecast` tells agents to parse
   `current.current_count` and `forecast.current_count` side by side, but
   the two blocks are in opposite units (free spaces vs occupied vehicles)
   with `tunit: ""` on both. Following the parse hints faithfully produces
   "Park Terme goes from 46 free to 483 free" when it stays 92% full. The
   agent caught it only because the numbers were physically implausible.
   Category: docs or skill guidance. If a second round hits it, the bounded
   CLI fix is to label units on both diagnostic blocks - not to convert
   silently.
5. The curated `odh traffic` layer answers `count: 0` for South Tyrol road
   questions while the live provincial bulletin exists only in Tourism
   `/v1/Announcement`, reachable through raw `odh call` (3 tasks). The
   frozen-feed warning names the fallback endpoint, which is the only
   reason three agents reached correct answers - but each then reinvented
   paging, de-duplication, the `EndTime`-as-retirement-marker semantics,
   and the fact that `Active` stays true on retired records. Category: docs
   or skill guidance. Explicitly **not** a new command: an
   `odh announcements search` would be the endpoint-specific wrapper the
   clean-CLI rule rejects, and the underlying problem is an upstream feed
   that stopped updating.
6. `a22 status` inspects the empty event feed and the two-months-future
   TrafficForecast, but not LinkStation `lds_leggeri_desc` /
   `lds_pesanti_desc`, which is the only live A22 traffic layer. An agent
   trusting the curated command concludes ODH has no live A22 traffic,
   which is false. Category: docs or skill guidance for now (document the
   datatypes and the `source=a22` Announcement bulletin); folding LDS into
   `a22 status` is a plausible narrow feature on a second occurrence.
7. The datasets catalog maps "tourism events" solely to `/v1/EventShort`,
   the NOI Techpark room calendar, and `diagnostics tourism-events`
   inherits that. `datasets guide "events near a town today"` returns 0
   matches. `/v1/Event` - the endpoint with GpsInfo, occurrence arrays and
   radius filtering - is not in the catalog at all. Round 1 logged this as
   "watch, revisit only if agents keep needing `/v1/Event`". They did.
   Category: docs or skill guidance (catalog data, not command surface).
8. `mobility latest --help` (`internal/commands/mobility.go:385`) shows
   `--data-type vehicle-count --origin A22`; that datatype does not exist
   in the A22 catalogue, and the real name returns zero rows anyway.
   Category: docs or skill guidance.
9. Agents asserting unreproducible CLI defects in their feedback (5
   occurrences across 4 attempts: `transit departures` exit 0, unknown-flag
   exit 1 vs 2, two "silent truncation" claims where the warning does fire,
   one truncation suspicion on a stop search that genuinely has 20
   results). None of these reached the user-facing answer except in
   `transit-auer-brenner-delay-probability`, which is why that one
   partialled. Category: agent reasoning. Acting on this channel
   uncritically would have driven at least two wrong CLI changes; judges
   re-running the exact bare invocation is what caught it, and that step
   should stay mandatory in the protocol.
10. `--origin` is a post-fetch local filter on `mobility stations` /
    `latest`, so a low `--limit` returns `count: 0` for an origin that
    exists, while `--where 'sorigin.eq."..."'` is server-side and correct.
    `--data-type` accepts comma-separated upstream lists. Neither is
    documented. Category: docs or skill guidance.
11. `traffic search --from/--to` passes the range upstream correctly but
    stale open-ended rows with no end date still return, so a single-day
    2026 query reports `count: 59` on rows dated 2025. Category: watch. The
    staleness warning already fires and the agent read it correctly; a
    skill note next to the existing warning is enough unless it misleads
    someone.
12. Round 1 item 3 (silent truncation on `mobility datatypes` / `stations`)
    is **closed**. The v0.4.1/v0.4.2 always-on truncation reporting fires
    correctly; judges reproduced it at `--limit 1000` and 20000 on the two
    attempts that claimed otherwise.

### v0.4.1/v0.4.2 warning surface

The new warnings carried three of the four traffic and EV tasks. The
truncation ladder was the decisive signal in
`dataset-guide-discovery-first` and `mobility-latest-fresh-availability`:
without it, `--limit 1000` reports a single-provider EV world. The
data-derived frozen-feed disclosure named exact dates (2025-07-23,
2025-10-08, 2025-10-13), which is what let three agents refuse a false
all-clear rather than reporting "roads are clear". Upstream error
propagation got one real exercise - the expired transmodel TLS certificate
surfaced as an error, not an empty result.

One gap the new warnings do not close: `diagnostics ev-charging` returns
`verdict: usable` while its own "inspected 10000 upstream rows; increase
`--request-limit`" warning is active, even when the capped result set is
entirely out of region. The verdict should degrade when the request-limit
cap was hit. One occurrence - watch.

## Data Findings Worth Keeping

- ALPERIA, historically the main South Tyrol EV operator, publishes nothing
  current: 7,677 stations, all inactive, newest measurement 2024-09-17,
  6,184 rows frozen at May 2018, every value 0.
- `EChargingStation` is 99% Swiss by live row count: 13,389 of 13,517 fresh
  active rows are BFE (`country: CHE`). The genuinely local live picture is
  128 points, 55 of them free.
- `sactive: true` is not a freshness signal: Neogy's 958 rows are all
  active and two months stale; Nevicam's are from July 2021.
- The PROVINCE_BZ Mobility Timeseries event feed is frozen ~10 months. The
  live provincial road bulletin now exists only in Tourism
  `/v1/Announcement`, where `EndTime` doubles as a retirement marker and
  `Active` stays true on retired records.
- A22: `LinkStation` `lds_leggeri_desc` / `lds_pesanti_desc` (90 active
  links, refreshing every few minutes) and `source=a22` Announcements are
  live; all numeric speed/flow/density/count datatypes still return zero
  open rows, consistent with round 1. No A22 history: a dated LDS query
  returns 0 rows.
- `parking-forecast-*` values are occupied vehicles, not free spaces, and
  `-rmse-*` has been dead since 2025-10-15; the fresh `-low-`/`-high-`
  bands are the usable uncertainty range. skidata Meranarena lots report
  sentinel values (9753/9999) that pass through as valid measurements.
- Tourism `/v1/Event` `DateBegin`/`DateEnd` is a season envelope, so
  `begindate`/`enddate` filtering needs a local `EventDate[]` re-check;
  coordinates are organiser offices, not venues (81 events, 55 points, one
  hike 50 km from its own coordinate).
- `EventShort` `onlyactive=true` still returns January 2018 NOI/Eurac room
  bookings with no GPS, unchanged from round 1.
- The STA GTFS archive is 132,534,630 bytes; stop names are Italian-only
  (`sinich`, `truden`, `bahnhof meran` all return zero).

## What To Change

Only items 1 and 2 change the CLI; both are repeated mechanical failures,
not one-off task difficulty.

1. **CLI** - let the archive fetch honour the global `--timeout` (or add an
   explicit archive-fetch budget), resume via a `.part` file, and make the
   failure name the archive size, the budget, and the resolved cache path
   instead of a bare `context deadline exceeded`. Four attempts blocked
   this round; one partial caused directly.
2. **CLI** - accept `--json` / `--format json` as no-ops on JSON-only
   commands (`diagnostics *`, `apis`, `mobility events`). Logged in round 1
   with an explicit recurrence trigger; recurred five times.
3. **Docs** - `recipes.json` `ev-current-availability`: drop the hardcoded
   ALPERIA, raise the discovery limit past the truncation warning.
4. **Docs** - `recipes.json` `parking-current-plus-forecast`: state that
   `current` is free spaces and `forecast` is occupied vehicles, and that
   `--forecast-minutes N` is N minutes from the model's
   `mtransactiontime`, not from query time.
5. **Docs** - add the `/v1/Announcement` fallback (PROVINCE_BZ and
   `source=a22`) to SKILL.md and recipes, including `EndTime`-as-retirement
   and `Active`-stays-true semantics.
6. **Catalog** - add `/v1/Event` to the datasets catalog and stop routing
   "tourism events" solely at `EventShort`.
7. **Docs** - A22 LinkStation LDS datatypes; fix the `vehicle-count`
   example in `mobility latest --help`; document `--origin` as a post-fetch
   filter versus server-side `--where`, and comma-separated `--data-type`.
8. **Watch, no change** - `diagnostics ev-charging` verdict not degrading
   when the request-limit cap is hit; `traffic search` date range admitting
   stale open-ended rows; no `traffic areas` discovery command; `a22
   status` not covering LinkStation LDS.
